O produto, em uma frase

Jogador aperta um botão na quadra. Os ~20 segundos anteriores (buffer circular na Raspberry Pi) mais 3 segundos depois viram um MP4, sobem para a nuvem e aparecem na galeria do QR. Os vídeos expiram em 7 dias.

Isto não é NVR, não é live, não é transcodificação na nuvem. O gatilho é local (ESP32 + Pi). A nuvem só recebe, guarda, lista e entrega o arquivo.

1. Visão geral e papéis

Três camadas, cada uma com um trabalho só:

CamadaOndeFazNão faz
QuadraCâmera PoE + ESP32 + botãoImagem contínua RTSP; aperto físicoUpload, galeria, internet
BordaRaspberry Pi 3 B+Buffer, concat, MP4, fila, PUT no Worker, heartbeatServir o site; transcodificar na nuvem
NuvemCloudflare Worker + D1 + R2Slot de upload, storage, galeria, painel, portal, retençãoFalar com a câmera ou com o ESP

O Worker não alcança a câmera. A API local do agente escuta só 127.0.0.1. Quem dispara o clip é: botão USB-serial, POST /local/replay na Pi, tecla no terminal, ou T no serial.

Fuso de galeria e retenção: Brasilia UTC-3 fixo (sem horario de verao). Datas na UI sao "hoje" em BRT, nao no relogio do celular.

Retenção padrão: RETENTION_DAYS=7. Clip ganha expires_at = recorded_at + 7 dias no pedido de slot. Cron diário apaga D1 + objetos R2 vencidos.

4.2 Buffer circular

ffmpeg contínuo, vídeo copy, sem áudio, segmentos MPEG-TS:

-rtsp_transport tcp -timeout 5000000 -i RTSP_URL
-map 0:v:0 -c:v copy -an
-f segment -segment_time 2 -segment_wrap N -reset_timestamps 1
-segment_format mpegts /dev/shm/replay/seg_%03d.ts

SEGMENT_WRAP = ceil((PRE+POST+10)/SEGMENT) + 5. Com pre 20 / post 3 / seg 2 ≈ 22 arquivos.

-timeout 5000000 é 5 s em microsegundos: câmera some → ffmpeg sai → supervisor relança.

Backoff de restart: 1, 2, 5, 10, 30 s. Se o processo durou mais de 60 s, o backoff zera. Cada saída gera evento ffmpeg_restart.

Watchdog de stall: se o ffmpeg está vivo mas nenhum .ts novo por max(3×SEGMENT, 6) s, manda SIGKILL (câmera “congelada”).

Senha RTSP é mascarada no stderr antes de ir ao journald.

4.3 Montagem do clip

  1. Marca busy, evento press, espera POST_ROLL_SEC.
  2. Lista segmentos por mtime. Soma duração real (intervalo entre mtimes) porque o GOP da câmera faz cada .ts durar mais que 2 s.
  3. Exige pelo menos 3 segmentos e cobertura ≥ metade de (pre+post). Senão: buffer ainda frio.
  4. Concat ffmpeg -f concat -safe 0.
  5. Se OUTPUT_FORMAT=story: crop central 9:16 (ou transpose 90/270) + scale=540:960 + libx264 ultrafast CRF 26, 3 threads, yuv420p, +faststart, sem áudio.
  6. Se vazio: -c copy + faststart (landscape nativo).
  7. Thumb: um JPEG (largura 480) extraído do MP4.
  8. Escreve {clip_id}.mp4 + {clip_id}.json (clip_id, court_key, recorded_at) na outbox. JSON via write+rename atômico.

Gera UUID do clip na Pi. O slot no Worker é idempotente nesse id — queda de internet no meio do PUT não duplica.

4.4 Upload

  1. POST /edge/clips/upload-slot com Authorization: Bearer EDGE_TOKEN, body { court_key, clip_id, recorded_at }.
  2. PUT /edge/clips/:id/content — corpo = bytes do MP4.
  3. PUT /edge/clips/:id/thumbnail — JPEG.
  4. Apaga a entrada da outbox; evento clip_ok.

Falha: backoff 5, 15, 30, 60, 120, 300 s. Evento clip_fail. A outbox sobrevive a reboot.

4.5 HTTP local (127.0.0.1)

MétodoPathFunção
GET/UI mínima (botão de replay no browser da Pi)

Teclado no TTY: Enter, Espaço ou R também disparam.

4.6 Serial USB — detalhe que evita reset eterno

Um único openSync(path, "r+"). Dois streams na mesma path erguem DTR duas vezes e o ESP fica em boot loop. Depois do open, pulso RTS/DTR via Python embutido (releaseEspReset) e stty -hupcl para não derrubar DTR ao fechar.

Primeiro chunk após conectar costuma ser lixo de boot (rst:0x1 POWERON_RESET) — o agent loga só esse primeiro pedaço. Linhas seguintes HB/BTN não poluem o journal.

4.7 Heartbeat (payload)

JSON aproximado enviado a cada 60 s, mais eventos pendentes (máx. 50 por request, 500 em disco):

  • agent_version = 0.4.5
  • temp_c, throttled (vcgencmd)
  • load1, mem_free_mb, mem_total_mb, uptime_s
  • buffer_alive, segments, busy, queue_len
  • button_alive (HB recente)
  • ffmpeg_restarts_1h
  • events[]: press | clip_ok | clip_fail | ffmpeg_restart | boot | queue_drop com at ISO e detail ≤ 200 chars

npm run admin:device -- --venue=venue-demo --name="Pi Arena Demo"

Imprime EDGE_TOKEN=... uma vez. Cole no edge.env e systemctl restart replay-agent.

powershell -File edge/pi/update.ps1 -PiHost replay-quadra1 -Full

-Full reenvia install.sh, unit e udev. Sem -Full só troca agent.mjs e restart.

10. Autenticação e segurança (o que o código faz)

  • Token do Pi nunca é persistido em claro; só SHA-256.
  • Admin token comparado em tempo constante (hash + timingSafeEqual).
  • Sessões admin/portal: HMAC de accountId.exp com chave derivada de SESSION_SECRET (scopes separados). Conta desativada invalida no próximo request.
  • Link da arena: token aleatório, guarda hash; Referrer-Policy no redirect; cookie de portal.
  • API local do agent bound a 127.0.0.1 — não entra no túnel Cloudflare.
  • R2 privado; Range requests no GET do MP4.
  • Logo sem SVG.
  • IP de analytics hasheado com sal + dia.
  • /painel e /arena mandam noindex, nofollow.
  • Galeria /q e /g são públicas: é o produto do QR.

11. Observabilidade

  • Worker: observability + traces no wrangler.
  • Painel: device online se last_seen < 180 s; issues do último payload.
  • Cron 5 min: alerta persistido (mesmo sem e-mail).
  • Pi: journalctl; health local; temp/throttle no heartbeat.

Com e-mail desligado, “envio” retorna sucesso no log email_skipped para o alerta não ficar pendente para sempre.

13. Operação do piloto — checklist

  1. Pi ligada, Wi‑Fi ok, cabo no switch, cam no PoE.
  2. systemctl is-active replay-agent = active.
  3. curl 127.0.0.1:8788/health → buffer_alive: true, busy: false. Após boot, ~25 s de warm.
  4. ESP em /dev/replay-button. LED GPIO 2 fixo = HB/ACK.
  5. Aperto: GPIO 4 no GND. LED pisca → clip → 3 piscadas.
  6. Conferência: /q/demo01 ou /g/demo.
  7. Simular sem botão: POST http://127.0.0.1:8788/local/replay via SSH.

Offline no painel: 3 min sem heartbeat. Alerta de cron: 10 min. Filas: 0 no health = upload em dia.

Desligar Pi/câmeras é seguro. Clips já no R2 continuam até expirar. Ao religar, o agent aquece o buffer e o alerta offline fecha sozinho no cron.

Limite explícito deste documento. Não descreve live (YouTube/Instagram), NVR 24h, transcode na nuvem, troca da Pi, VLAN, nem segundo agent em systemd. Isso não está implementado. O que está no ar é o pipeline botão → buffer → MP4 → R2 → galeria 7 dias, com painel e portal da arena.
